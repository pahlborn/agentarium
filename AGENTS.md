# Agentarium working instructions
Read `governance/agentarium-rulebook-v1.2.md` and `governance/agentarium-process-v1.2.md` for the current candidate team contract and its adoption limits. Check the task's current baseline and explicit decisions before work. These instructions do not expand permissions or authorize merge, publication, infrastructure changes or paid runs.

Never invent specialist participation, results, tests, costs, timestamps or approvals. Distinguish observed evidence, reported claims, proposals and unknowns. Role definitions and historical runs are not current connectivity. Claude roles require real Claude execution; do not impersonate them with ChatGPT agents.

Use the smallest useful scope. Seek Forge's architecture/feasibility judgment before material technical commitment and test the riskiest real integration early. Challenge Atlas when evidence or approach is wrong. Test the actual required surface; required unavailable proof blocks acceptance. Peter approves Epics and material changes, not each story/test.

Atlas owns routing, evidence reconciliation, truthful progress and completion. Cadence receives triggered process findings through a real channel, not an assumed background presence. Missing feedback stays pending. Record exact task/version, relevant baseline, result, limits and next owner. Never make Peter copy messages between runtimes.

For material product work read `governance/product-development-practice-v1.md`. Start with user value and a testable goal, test the decisive uncertainty early and use applicable shared completion criteria. Peter owns product priority; Atlas coordinates; Cadence holds the agile-coach/Scrum-Master function when actually invoked. Everyone shares success/failure while named accountabilities remain explicit.
